VIVARY

Virtualized Isolated Verifiable Agent Runtime Yard

A governed runtime for isolated, auditable AI agents on a shared host. VIVARY provides a hardened environment with strict security boundaries, comprehensive audit trails, and zero-exposure credential management.

View on GitHub

Core Benefits

Triple-Boundary Isolation

Each agent is isolated via systemd-nspawn jails, Btrfs subvolumes, and firewalled veth interfaces. No raw network access beyond the LLM API endpoint.

Zero-Exposure Governance

Agents never hold API keys or credentials. keeperd resolves references to a secure vault only at the gateway invocation layer.

Capability-as-CLI

Capabilities appear as self-documenting CLI tools. The Ward handles syntax translation into MUS frames, while keeperd remains the semantic authority.

Comprehensive Auditability

Every request and response is recorded in a binary MUS audit trail. Unix-style debug tooling allows operators to inspect and decode the runtime's actions.

Identity Integrity

Agent identity (FromID) is stamped by keeperd based on the physical pipe a message arrived on. Peer impersonation is structurally impossible.

Cross-Platform Parity

Packaged as a NixOS LXD container via a distrobuild script, ensuring identical execution on Linux, Windows 11 (WSL2), and macOS (OrbStack).

Architecture Overview

VIVARY separates concerns through a dual-binary model:

  • Vivary Keeper (keeperd): The central daemon, message router, policy enforcer, and credential vault.
  • Vivary Ward (ward): The per-agent control plane inside each nspawn container, managing the LLM subprocess lifecycle and tool translation.

Communication occurs over a tightly controlled MUS-formatted stdio pipe, ensuring O(1) performance and zero-allocation routing.
